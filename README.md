# Arrow Out! 🏹

![CI](https://github.com/parya5103/Fletch_Game/actions/workflows/ci.yml/badge.svg)

A mobile-first **tap-away arrow puzzle** game — an **installable PWA**, zero dependencies, fully offline-capable. **1000 levels** of winding arrow paths on boards from 12×12 up to dense 65×65. **3 free hints per level**, hearts, timed bonus objectives, daily challenges, achievements, streaks, skins, stars and synthesized background music.

## How to play

- The board is a grid of **winding arrow paths** — each piece is a connected corridor of cells with one arrowhead at its head.
- On dense boards, tap the overview to zoom to readable 44px cells; drag to pan, pinch or use **+/−** to zoom, and **Fit** to see the whole puzzle. Hints focus a removable arrow. Navigation never spends hearts.
- Tap a piece to launch it: it slides out **like a snake**, following its own path and exiting along the arrowhead's direction.
- A piece can launch **only if its head's exit corridor is clear** — no other piece may sit between the head cell and the board edge along that direction. A blocked tap is a mistake (1 of 3 hearts lost).
- Clear every arrow to win the level. Clear all **1000 levels** to complete the campaign 🏆
- **Undo** reverses your last launch, **Restart** resets the level.
- **Hints:** 3 free per level (a badge on the Hint button counts them down). After that, watch a short demo ad to reveal another hint.

## Difficulty ramp

| Levels | Board | Real arrows |
|---|---|---|
| 1–10 | 12×12 → 14×14 | 20–28 |
| 11–50 | 15×15 → 19×19 | 29–50 |
| 51–200 | 19×19 → 31×31 | 51–130 |
| 201–500 | 31×31 → 46×46 | 131–300 |
| 501–800 | 46×46 → 60×60 | 301–500 |
| 801–1000 | 60×60 → 65×65 | 501–600 |

Counts interpolate between design anchors without tier resets. Each piece occupies its own connected cells, with a direction aligned to its final segment. The campaign grows paths backwards from clear heads in a deterministic center-out order, with bounded retries using shorter paths if needed. Generation rejects an incomplete target or invalid solution. Color/order families provide variation; every 50th level is a milestone, and levels ending in 5 retain timed bonuses.

The rectangular viewport fills the available gameplay area, with uniformly scaled Fit and independent pan bounds. Generated puzzles remain square; zoom uses the extra portrait height without stretching or changing solutions. Dense boards use an overview plus a zoomable viewport, exact cell ownership for hit testing, offscreen path culling, and a cached layer for stationary arrows. Canvas memory depends on screen size rather than board size. Existing saved puzzles retain their original geometry and progress; starting/restarting a campaign level uses the new generator. No save migration is needed. Daily challenge generation is preserved.

See [density validation](audit/density-2026-10-17.md) for measured counts, complexity, performance, and limitations.

## Every level is solvable — guaranteed

Levels are generated by **reverse placement**: pieces are carved one by one onto the board mask, and a piece is only laid down where its winding path can still exit cleanly against the pieces already placed (the exit corridor of its head must stay clear). Reversing that build order always yields a valid clear order, so every level can be finished with zero mistakes, the Hint button can always point to a safe piece, and deadlock states are impossible. All 1000 levels plus the daily challenge are verified solvable with correct hints — and the CI workflow re-verifies this on every push.

## Security & privacy (v3.7)

- **Client-side saves**: progress, coins and skins live in your browser's `localStorage`. That is a feature (private, offline, no account) — but it also means a user who edits their own `localStorage` can change their own coins/progress. The game sanitizes saves on load (clamps ranges, drops junk fields, never deletes valid progress), but **localStorage is not cheat-proof and is not meant to be** — there is nothing worth cheating against. Real server-authoritative validation would only become necessary for online leaderboards, purchases or multiplayer, all of which would require a backend this static site deliberately does not have.
- **Notifications are real Web Push with no paid backend**: the push "server" is the scheduled `.github/workflows/notify.yml` workflow (GitHub Actions cron, five sends a day at fixed IST times). When a player toggles Daily reminders ON, the game auto-saves their push subscription to a Supabase `push_subscriptions` table using the public anon key — the intended policy is restricted anonymous subscription writes and service-role-only roster reads. Actual RLS, grants, endpoint uniqueness, duplicate-upsert permissions and delete ownership must be verified in Supabase; client code cannot prove them. The workflow uses the service-role credential only on the sender to fetch the roster and remove expired endpoints. One-time setup: add the `PUSH_VAPID_PRIVATE_KEY` and `SUPABASE_SERVICE_KEY` repo secrets (the VAPID key pairs with the public key in `js/pwa.js`). The permission prompt only ever fires from the deliberate Settings toggle; toggling off attempts both roster deletion and browser unsubscription and reports failures. Browser subscription status does not prove server delivery. New saves default off; existing preferences remain intact. Push payloads and notification-click URLs are re-validated in the service worker (same-origin scope only). If GitHub disables the schedule after 60 days of repo inactivity, re-enable it from the Actions tab.
- **Service worker hardening**: push payloads are untrusted — malformed JSON, wrong types, oversized text and non-local icons are rejected without crashing; notification clicks only open same-origin URLs inside the app scope (`javascript:`, `data:` and external origins are rejected and fall back to the game home screen).
- **CSP**: set via a `<meta>` tag (`script-src 'self'; object-src 'none'; base-uri 'none'`; styles keep `'unsafe-inline'` because the UI uses inline `style` attributes and a critical inline CSS block). `connect-src` allows only the game's own origin plus the single Supabase API origin used to save notification subscriptions — normal gameplay uses no other external API; opt-in push subscription also involves the browser vendor’s push service. Meta-tag CSP cannot express `frame-ancestors`, HSTS, COOP/COEP or `report-only` — those need HTTP response headers, which ordinary GitHub Pages configuration cannot set.
- **Supply chain**: GitHub Actions are pinned to immutable commit SHAs (`actions/checkout`, `actions/setup-node`, `treosh/lighthouse-ci-action`) and run with least-privilege permissions. The CI job is read-only (`contents: read`); only the screenshot/icon jobs that must commit back get `contents: write`.

## Run locally

Just open `index.html` in a browser, or serve the folder over HTTP so the service worker can register:

```bash
npx http-server .
# or
python3 -m http.server 8000
```

Run the automated checks locally (Node 20+; no dependencies):

```bash
node scripts/ci-test.js
node scripts/regression-test.js
node scripts/audit-test.js
node scripts/density-test.js
node scripts/cosmetics-test.js
timeout 180s node scripts/validate-levels.js
```

The independent validator loads production code, checks geometry and occupancy, solves every campaign level in three seeded removal orders, checks hints and each actual removal at every step (all survivor blockers initially and every 32 moves), initializes every level through the game controller, and tests 366 daily seeds. Pass an optional JSON output path to save per-level results. Historical `audit/*validation.js` and `audit/level_test.js` entry points now run this same validator. Older checked-in audit reports are historical and are superseded by `audit/stabilization-2026-10-17.md`.

Browser validation requires Node 22+ and the already running shared Preview Chromium (no browser launch or npm dependencies):

```bash
node scripts/browser-density-test.js http://localhost:8000/ /path/to/output
```

It covers native touch events, 320/390px layouts, rendering with 4× CPU throttling, screenshots, and a real offline reload. Physical Android device performance still needs hardware testing.

The developer-only `js/tests.js` browser suite is not loaded by the game. Run it on a local QA profile; it exercises storage with temporary fixtures and restores the original save.
