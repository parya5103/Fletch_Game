# Arrow Out! 🏹

![CI](https://github.com/parya5103/Fletch_Game/actions/workflows/ci.yml/badge.svg)

A mobile-first **tap-away arrow puzzle** game — an **installable PWA**, zero dependencies, fully offline-capable. **1000 levels** of winding arrow paths on boards from 12×12 up to dense 65×65. **3 free hints per level**, hearts, timed bonus objectives, daily challenges, achievements, streaks, skins, stars and synthesized background music.

## How to play

- The board is a grid of **winding arrow paths** — each piece is a connected corridor of cells with one arrowhead at its head.
- On dense boards, tap the overview to zoom to readable 44px cells; drag to pan, pinch or use **+/−** to zoom, and **Fit** to see the whole puzzle. Hints focus a removable arrow. Navigation never spends hearts.
- Tap a piece to launch it: it slides out **like a snake**, following its own path and exiting along the arrowhead's direction.
- A piece can launch **only if its head's exit corridor is clear** — no other piece may sit between the head cell and the board edge along that direction. A blocked tap is a mistake (1 of 3 hearts lost).
- Clear every arrow to win the level. Clear all **1000 levels** to complete the campaign 🏆
- **Undo** reverses your last launch, **Restart** resets the level.
- **Hints:** 3 free per level (a badge on the Hint button counts them down). After that, watch a short demo ad to reveal another hint.

## Difficulty ramp

| Levels | Board | Real arrows |
|---|---|---|
| 1–10 | 12×12 → 14×14 | 20–28 |
| 11–50 | 15×15 → 19×19 | 29–50 |
| 51–200 | 19×19 → 31×31 | 51–130 |
| 201–500 | 31×31 → 46×46 | 131–300 |
| 501–800 | 46×46 → 60×60 | 301–500 |
| 801–1000 | 60×60 → 65×65 | 501–600 |

Counts interpolate between design anchors without tier resets. Each piece occupies its own connected cells, with a direction aligned to its final segment. The campaign grows paths backwards from clear heads in a deterministic center-out order, with bounded retries using shorter paths if needed. Generation rejects an incomplete target or invalid solution. Color/order families provide variation; every 50th level is a milestone, and levels ending in 5 retain timed bonuses.

The rectangular viewport fills the available gameplay area, with uniformly scaled Fit and independent pan bounds. Generated puzzles remain square; zoom uses the extra portrait height without stretching or changing solutions. Dense boards use an overview plus a zoomable viewport, exact cell ownership for hit testing, offscreen path culling, and a cached layer for stationary arrows. Canvas memory depends on screen size rather than board size. Existing saved puzzles retain their original geometry and progress; starting/restarting a campaign level uses the new generator. No save migration is needed. Daily challenge generation is preserved.

See [density validation](audit/density-2026-10-17.md) for measured counts, complexity, performance, and limitations.

## Every level is solvable — guaranteed

Levels are generated by **reverse placement**: pieces are carved one by one onto the board mask, and a piece is only laid down where its winding path can still exit cleanly against the pieces already placed (the exit corridor of its head must stay clear). Reversing that build order always yields a valid clear order, so every level can be finished with zero mistakes, the Hint button can always point to a safe piece, and deadlock states are impossible. All 1000 levels plus the daily challenge are verified solvable with correct hints — and the CI workflow re-verifies this on pull requests targeting `main`, pushes to `main`/`security-v*`, and manual runs.

## Security & privacy

- **Client-side saves**: progress, coins and cosmetics live in your browser's `localStorage`. That is a feature (local, offline, no account) — but it also means a user who edits their own `localStorage` can change their own coins/progress. The game sanitizes saves on load (clamps ranges, drops junk fields, never deletes valid progress), but **localStorage is not cheat-proof and is not meant to be** — there is nothing worth cheating against. Real server-authoritative validation would only become necessary for online leaderboards, purchases or multiplayer, all of which would require a backend this static site deliberately does not have.
- **Reminders are local**: `js/reminders.js` checks elapsed inactivity in the open page; it never subscribes to push or contacts Supabase. Optional system display uses `ServiceWorkerRegistration.showNotification`. Permission is requested once, only by the Allow button. Page timers can stop when suspended/closed; service workers have no reminder timer. Existing push subscriptions are only looked up for best-effort unsubscription. Historical provider records require separate operator deletion.
- **Service worker hardening**: no remote push listener remains. Notification clicks only use validated same-origin app-scope URLs; malformed/external destinations fall back to the game. An existing game window is focused without resetting its puzzle.
- **CSP**: the app uses meta `script-src 'self'; connect-src 'self'; object-src 'none'; base-uri 'none'`. Inline styles remain necessary for the UI. No provider API origin is allowed. Meta CSP cannot set frame-ancestors, HSTS or COOP/COEP; those require hosting response headers. Public text pages have their own inline styles and Contact script; the app's script policy is not a claim about those pages.
- **Supply chain**: Actions use immutable SHAs and least privilege. CI is read-only; screenshot/icon jobs that commit back have write permission. The old scheduled sender and `web-push` install were removed; no notification backend dependency remains.

### Architecture and invariants

- **Implemented:** static HTML/CSS plus script modules; no application package install, framework, build step, account login or cloud-progress sync. Older PR #2 proposed Supabase accounts; main at this baseline uses Supabase only for push subscriptions; this reviewed branch removes that integration. Do not restore obsolete accounts or remote push from old PR descriptions.
- `js/game.js` owns square board generation, rules, validators, hints and cosmetic catalogues. Pieces are disjoint ordered orthogonal cell paths (tail → head), with `dir` aligned to the final segment. Only another live piece in the **head exit ray** blocks a launch; body projections must not become blockers.
- Campaign heads are placed with clear exits, then tails grow backwards; reverse placement order solves the puzzle. Counts interpolate monotonically across anchors (1:20, 10:28, 50:50, 200:130, 500:300, 800:500, 1000:600). Generation retries deterministically and rejects incomplete/invalid boards. Daily challenges use the separate deterministic date-seeded generator. Never fake counts or duplicate paths.
- `js/main.js` controls load/restore, occupancy, input, hints, undo, bonuses and wins; `js/ui.js` controls dialogs/HUD, navigation and shop. Home → Continue restores a snapshot; level selection/restart generates that level anew. Home saves immediately; last-arrow restoration completes exactly once. Preserve stale-callback guards and one-time bonus rewards.
- `js/render.js` provides a **rectangular viewport around square puzzles**, uniform Fit, independent pan bounds, camera hit conversion, culling and cached stationary arrows. Zoom/focus gives 44px cells; drag/pinch/cancel must never launch or lose a heart. Two backing canvases follow viewport size at capped DPR2. Audio/haptics are optional; missing APIs cannot block core play.
- Home exposes Continue, Play, daily, map, shop, stats, achievements and settings. About/Contact/Privacy are linked on Home and Settings; How to play links to About. Public pages cross-link and return to the game. Shop has Board Skins/Arrow Skins tabs, **5 board themes and 17 arrow cosmetics**, including six distinct designs and free defaults. `GameCore.COSMETICS` is the source of IDs/prices. Live previews do not spend/equip; `Storage.cosmeticAction` atomically buys/equips using earned coins, prevents duplicate charges and rolls back persistence failures. No payments or ad SDK.

### Save compatibility

- Keep `arrowOut.v2` / `v:2`. Fields include `unlocked`, `best`, `cur`, `coins`, `stats`, `achievements`, `daily`, `streaks`, `loginRewards`, `bonusClaimed`, `sound/music/vibration/theme`, `installHidden`, `skin/owned`, `boardSkin/ownedBoards`, and `settings` (notifications, reduced motion, onboarding). Reminder fields are additive: `reminderMinutes` (60/90/120, default90), `systemNotifications` (defaultfalse), `notificationPrompted` (defaultfalse). The existing `notifications` boolean is preserved as the in-game reminder choice. Local `arrowOut.reminders.v1` stores activity; `arrowOut.reminderClaims.v1` stores delivery/test markers separately from progress. Only code holding the Web Lock may write claims, so stale activity flushes cannot erase them; enabled reminder activity writes are throttled to15s. PWA also uses the legacy local install-banner marker `ao-install-v9-reset`.
- `cur` carries level/date, dimensions, active shape indices, original path geometry, alive flags, hearts/mistakes/hints, recent undo IDs and remaining bonus time. Restore validates the complete snapshot before publishing state; retain original legacy geometry. In-memory undo is bounded to 100; persisted undo keeps 40. Failed/won runs clear `cur`; timed bonus claims survive replay/undo. Daily restores must match the current UTC date.
- `js/storage.js` sanitizes/normalizes saves, clamps ranges, ignores hostile/inherited keys and adds missing cosmetic defaults while preserving valid purchases/progress. v1 migration writes v2 successfully **before deleting the v1 backup**. Missing/blocked/quota-limited storage must leave play possible; do not promise persistence in that case. Coins/progress remain user-editable local data, not server-authoritative entitlements. Multi-tab conflict handling is not implemented.
- Settings → Reset all progress resets local progress/preferences and reminder timing and closes local notifications; it does not revoke OS permission, erase cached files or delete historical provider data. Worker updates must not clear saves, preferences or purchases. Do not rename stable cosmetic IDs or require a reset/cache purge as an update fix.

## Run locally

Just open `index.html` in a browser, or serve the folder over HTTP so the service worker can register:

```bash
npx http-server .
# or
python3 -m http.server 8000
```

Run the automated checks locally (Node 20+; no dependencies):

```bash
node scripts/ci-test.js
node scripts/regression-test.js
node scripts/audit-test.js
node scripts/reminders-test.js
node scripts/density-test.js
node scripts/cosmetics-test.js

Older checked-in audit reports are historical. Use the latest applicable dated report, including density, full audit, responsive/cosmetics and page-review reports, together with current source; the stabilization report predates PRs #5–#8.
