# Arrow Out! — Android release paths

This repository currently contains **two different Android application paths**. They have different package IDs and must not be treated as one interchangeable build:

| Path | Package ID | What it ships |
|---|---|---|
| Trusted Web Activity (TWA) | `com.aaryapratik.arrowout` | A thin Android wrapper around the live Arrow Out PWA at `https://gogocompany.in/arrowout/` |
| Native Kotlin app | `in.gogocompany.arrowout` | A separate Jetpack Compose application under `android-native/` |

Before creating or publishing a Play Console listing, confirm which package identity is intended. Do not upload the TWA and native app as updates to the same listing. A package ID becomes permanent after publication. The native app is a playable foundation but does not yet establish full feature parity with the web campaign; it needs its own gameplay, physical-device and release review.

## Existing TWA build path

- `android/twa-manifest.json` configures the TWA package `com.aaryapratik.arrowout`, the live GoGo Company URL, icons and Daily Challenge shortcut.
- `.github/workflows/twa-build.yml` builds a signed APK/AAB and a Digital Asset Links file when run manually.
- The former public `TWA signing key` workflow has been removed. **Never generate a signing keystore in GitHub Actions or upload it as a public artifact.**
- Generate the signing key privately and configure the protected Actions secrets by following [ANDROID_SIGNING.md](ANDROID_SIGNING.md). Never paste a keystore, base64 value or password into chat, commits, issues or logs.
- Optional AdMob app-open ads remain disabled unless the corresponding protected secrets are deliberately configured. Website AdSense is not included in the TWA. Read [ADMOB.md](ADMOB.md) before enabling app ads.

## Configure TWA signing

1. On a trusted private computer or Android/Linux environment, follow [ANDROID_SIGNING.md](ANDROID_SIGNING.md) to create and back up the keystore.
2. Add these repository Actions secrets: `TWA_KEYSTORE_B64`, `TWA_KEYSTORE_PASSWORD` and `TWA_KEY_PASSWORD`.
3. Verify the keystore and alias privately before building. Do not rotate the key after publishing; confirm Play App Signing and the upload-key arrangement in Play Console first if an app has ever been published.
4. Run **TWA APK build** manually from GitHub Actions. The workflow must upload only the signed APK/AAB and generated `assetlinks.json`, never the keystore or passwords.

If a signing-key artifact was generated by the former workflow before it was removed, assume that artifact may have been accessible to repository readers. Check the historical Actions runs/artifacts and determine whether the key was ever used for a Play upload. If it was exposed, follow the appropriate Play App Signing upload-key reset/recovery process; do not silently generate a replacement key.

## Digital Asset Links

Android verifies the TWA against:

`https://gogocompany.in/.well-known/assetlinks.json`

The root domain is served by the `gogo-website` repository. Generate the file from the actual signing certificate in the TWA build; never guess its SHA-256 fingerprint. Publish the generated file at `.well-known/assetlinks.json` in the root-domain repository, then verify that exact URL returns the expected JSON.

Without a matching Digital Asset Links file, the TWA can still open but Chrome may show browser UI and an unverified-site warning.

## Native Kotlin app path

The native Android implementation is in `android-native/` and uses package ID `in.gogocompany.arrowout`. Its GitHub Actions workflow is `.github/workflows/android-native-kotlin.yml`; it runs unit tests and builds a debug APK and release AAB artifact.

The native app is not the TWA wrapper. Before selecting it for Play publication, verify gameplay feature parity, save compatibility, touch/large-board rendering, lifecycle and offline behaviour on a physical Android device, configure its own release signing, and check its store package identity. A successful CI build is not a substitute for device QA or Play Console approval.

## Release checklist

- Confirm the chosen package ID and whether the listing is TWA or native Kotlin.
- Confirm the signing-key ownership, protected backup and Play App Signing arrangement.
- Test install, upgrade, progress preservation, offline launch, notification permission and opt-out on physical Android devices.
- Verify the current Play target API, Data safety declarations, ads declaration, content rating, privacy policy and store listing at submission time.
- For the TWA, verify the live Digital Asset Links file and exact website URL.
- Use internal testing before any production rollout.

The website privacy policy is `https://gogocompany.in/arrowout/privacy.html`. Play Console fees, target API deadlines and policy requirements can change; use the current Play Console instructions rather than relying on historical amounts or dates.
